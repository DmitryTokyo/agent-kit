# agent-kit

[English](README.md) · **Русский**

Набор скиллов для агента в любом харнессе, с которыми агент ведёт задачу от
постановки до pull request: заводит её в трекере, пишет план, режет его на маленькие тикеты, пишет тесты и код,
проверяет себя и коммитит. Ты утверждаешь ключевые шаги и смотришь итог в pull request.

Кит пригодится, если ты:

- работаешь над проектом один и пишешь код вместе с агентом, возможно в нескольких харнессах;
- хочешь, чтобы агент во всех твоих проектах работал по одному процессу, а не по правилам, которые каждый раз
  объясняешь заново;
- ведёшь задачи в трекере и хочешь, чтобы ветки и коммиты были к ним привязаны;
- хочешь, чтобы код проходил через тесты и ревью, а агент никогда не пушил в основную ветку.

Для разовых правок и вопросов он не нужен: процесс там только мешает.

## На чём проверено

- Харнессы: Claude Code, OpenCode, Codex.
- Модели: Claude, DeepSeek.

Другой харнесс заработает, когда в `docs/agents/harness.md` появится его секция: `bootstrap` напишет её по твоим
ответам.

## Это заготовка

Кит — стартовая точка, а не готовый набор. После установки скиллы лежат в проекте обычными файлами в
`.agents/skills/`, и их стоит подгонять под проект: под стек, трекер, твои привычки и ошибки, которые агент делает
именно здесь. Правь их прямо в проекте.

Расходиться с китом нормально. `sync` про каждую правку спрашивает, общая она или только для этого проекта, а правка
«только здесь» сохраняется при обновлениях из кита. В кит стоит забирать только то, что пригодится в любом проекте.

## Установка

1. Склонируй кит:

   ```bash
   git clone git@github.com:DmitryTokyo/agent-kit.git ~/dev/personal/agent-kit
   ```

2. Закоммить всё в проекте: установка ляжет одним диффом.
3. Открой агента в корне проекта и напиши:

   > Прочитай `~/dev/personal/agent-kit/skills/bootstrap/SKILL.md` и следуй ему.

4. Агент прочитает проект и пришлёт вопросы одним сообщением, к каждому — предложенный ответ. Два ответа выбираешь
   только ты: префикс скиллов (`ag` → скиллы называются `/ag-develop`, `/ag-orchestrate`) и ключ задач в трекере
   (`AG`).
5. Агент покажет, какие файлы создаст и изменит. После твоего «да» поставит скиллы и настроит проект.
6. Доделай руками:
   - включи проверку сообщений коммитов:

     ```bash
     pre-commit install --hook-type commit-msg
     ```

   - заполни места, которые агент не смог заполнить сам, — он перечислит их в отчёте;
   - проверь `git diff` и закоммить.

## Как пользоваться

Пиши агенту обычным текстом — нужный скилл подключится сам. В примерах префикс `ag` и ключ `AG`.

**Новая задача от начала до конца:**

```text
Заведи задачу: покупатель выбирает пункт выдачи на карте.
Напиши план для AG-55.
/ag-to-tickets AG-55
/ag-orchestrate AG-55
```

`create-plan` сначала классифицирует задачу — ценность для продукта, тип работы, риск — и выбирает маршрут:
известное локальное решение или сначала исследование. Потом пишет для тебя один короткий `plan.md`: результат,
критерии, границы, проверки на каждое последствие и нужно ли твоё ревью. Ты утверждаешь его один раз; агент
возвращается к тебе только при отклонении. Маленькая задача идёт сразу в `develop`. Большая — через `to-tickets`:
один тикет — один коммит, не больше 100 строк кода, тикеты собраны в части, одна часть — одна ветка и один pull
request. `orchestrate` берёт следующую часть и проводит каждый тикет: сабагенты пишут тесты и код, проверяют их и
коммитят.

**Ревью и pull request:**

```text
/ag-code-review AG-55 pickup-step       ← в новой сессии, лучше другой моделью
/ag-merge-request                       ← пушит и открывает pull request
Я прошёл PR, разбери мои комментарии.   ← ты оставил комментарии на диффе
PR смёржен.                             ← /ag-close-merge-request: трекер, Done, уборка
```

**Без тикетов:**

```text
Почини: ФИО с точкой в конце не принимается.
Добавь тесты на выбор пункта выдачи.
Подготовь коммит.
Задавай мне вопросы по этому плану по одному.
```

**Обменяться правками с китом** — забрать свои правки скиллов в кит и получить новое из кита:

> Прочитай `~/dev/personal/agent-kit/skills/sync/SKILL.md` и следуй ему.

### Все скиллы

| Скилл | Что делает |
| --- | --- |
| `create-task` | заводит задачу в трекере |
| `create-plan` | классифицирует задачу, пишет исследование, план для разработчика и инструкцию для агента |
| `to-tickets` | режет план на тикеты и части |
| `orchestrate` | проводит следующую часть тикетов, один коммит на тикет |
| `tdd-develop` | делает один тикет: сначала тест, потом код |
| `develop` | пишет код без тикета или по тикету без тестов |
| `test-writer` | пишет unit-тесты и E2E-сценарии |
| `recon` | изучает незнакомый код перед задачей и возвращает короткую сводку |
| `code-review` | проверяет часть или дифф по правилам и плану, ставит уровень ревью и проверки |
| `hygiene-review` | ищет в изменённых файлах то, что пропускают линтеры |
| `merge-request` | пушит, открывает pull request, разбирает твои комментарии |
| `close-merge-request` | после мёржа: ссылка на pull request в трекер, задача в Done, уборка веток и папки |
| `git-commit-message` | делит изменения на коммиты и предлагает сообщения |
| `grill-one` | задаёт вопросы по плану по одному, ищет дыры и противоречия |
| `business-questions` | ведёт вопросы к бизнесу в трекере; модуль, по умолчанию выключен |

## Что получишь

- **Один процесс во всех проектах.** Скиллы общие, а всё про конкретный проект — команды, трекер, правила кода —
  лежит в его `docs/agents/`. Новый проект получает тот же процесс после одного `bootstrap`.
- **Один короткий план.** До кода ты читаешь один экран — результат, критерии, границы, проверки — и утверждаешь его
  один раз.
- **Маленькие шаги.** Тикет — один коммит, часть — один pull request. По карте тикетов видно, что сделано и что
  осталось.
- **Ревью по риску.** Агент проверяет каждое изменение и пишет в pull request, какое последствие закрывает каждая
  проверка. Ты смотришь, только когда план так говорит, и только названные места.
- **Основная ветка под защитой.** Агент не пушит в неё — это запрещено в файле прав каждого харнесса. Его коммиты
  подписаны его харнессом (`Claude`, `OpenCode`, …), твои — тобой, поэтому в истории видно, кто что менял.
- **Правки не теряются.** Поправил скилл в одном проекте — `sync` предложит забрать правку в кит, и её получат
  остальные проекты.

## Как устроено

Скиллы не знают ничего о проекте. Все факты — пути, команды, трекер, правила — они читают из файлов `docs/agents/*.md`
самого проекта. Эти файлы называются контрактом: кит даёт заготовки, проект их заполняет.

### Что в репозитории

| Папка | Что | Куда попадает в проекте |
| --- | --- | --- |
| `skills/` | 15 скиллов и `bootstrap`, `sync` | `.agents/skills/<префикс>-*` (`.claude/skills` ссылается туда); `bootstrap` и `sync` не копируются |
| `contract/` | заготовки `docs/agents/*.md`; `<!-- fill: ... -->` — что заполняет проект | `docs/agents/` |
| `packs/` | пакеты — правила стека: `python`, `django` | дописываются в `code-rules.md`, `hygiene.md`, `testing.md` |
| `repo/` | разделы `CONTRIBUTING.md`, сниппет `AGENTS.md`, `.claude/settings.json`, правила Codex, pre-commit хуки | корень проекта |
| `scripts/render.sh` | кит на нужном коммите с подставленным префиксом | используют `bootstrap` и `sync` |
| `examples/tg-sales-bot/` | заполненный контракт живого проекта | образец для заполнения |

### Контракт: docs/agents/

| Файл | Что в нём |
| --- | --- |
| `domain.md` | `CONTEXT.md`, ADR, глоссарий |
| `issue-tracker.md` | трекер, ключ задач, инструменты, язык задач, где лежат рабочие файлы |
| `product.md` | документ с поведением, акторы, что видно только руками, E2E-актор |
| `stack.md` | стек, раскладка кода, команды `check` / `unit` / `e2e` / `one-test` / `migrate`, подсчёт строк |
| `git.md` | формат коммита, основная ветка, ветки задачи и частей, как открыть PR и разбирать его треды, авторство агента |
| `harness.md` | роли, уровни моделей и действия по каждому харнессу: сабагенты, модели, вопросы пользователю, подпись агента |
| `code-rules.md` | слои, где лежит код, нарезка тикетов, правила кода |
| `hygiene.md` | чеклист проверки изменённых файлов |
| `testing.md` | стек тестов, БД, моки, размещение файлов, E2E-харнесс, эталонные тесты |

### Модули

Модуль — необязательная часть кита. По умолчанию модули выключены, `bootstrap` спрашивает про каждый:

- `business-questions` — темы вопросов к бизнесу в трекере и правило «не закрывать задачу, пока ответы не пришли».
  Для своих проектов не нужен.
- `codegraph` — раздел «Code search» в `AGENTS.md`; предлагается, только если в проекте есть `.codegraph/`.

### Стек без пакета

Пакеты есть для Python и Django. Для другого стека (FastAPI, Go) `bootstrap` заполнит `code-rules.md`, `hygiene.md`
и `testing.md` с твоих слов и по коду. Когда правила устоятся, попроси `sync` сделать из них пакет — второй проект
на том же стеке получит их сразу.

### Как работает sync

- **Проект → кит.** `sync` покажет каждую правку скиллов и пакетов с прошлой синхронизации. На каждую ты отвечаешь:
  `в ядро` (забрать в кит), `оставить` (только в этом проекте) или `откатить`. Правки `в ядро` становятся коммитом в
  `agent-kit`; push — после твоего «да».
- **Кит → проект.** Изменения кита вливаются трёхсторонним слиянием поверх твоих локальных правок, конфликты `sync`
  покажет и спросит. Изменения `contract/` и `repo/` придут предложениями.

Факт о проекте — путь, команда, имя трекера — в кит не попадает: его место в `docs/agents/`.

### Плейсхолдеры и метки

| Метка | Где | Чем заменяется |
| --- | --- | --- |
| `{{p}}` | skills, contract, repo | префикс скиллов проекта |
| `{{work}}` | skills, contract, repo | рабочая папка файлов задач, по умолчанию `.ai` |
| `{{KEY}}`, `{{key}}`, `{{main}}` | repo | ключ задач, он же строчными, основная ветка |
| `<KEY>`, `<key>` | skills | не заменяется: скилл читает ключ из `docs/agents/issue-tracker.md` |
| `<!-- pack:NAME -->…<!-- /pack:NAME -->` | contract | текст пакета; по меткам `sync` находит его в проекте |
| `<!-- module:NAME -->…<!-- /module:NAME -->` | contract, repo | остаётся или вырезается вместе с модулем |

В `examples/` пустая пара `<!-- pack:NAME -->` означает «здесь текст пакета».
