# agent-kit

Скиллы, с которыми агент ведёт задачу от постановки до pull request. Он заводит задачу в трекере, пишет план, режет
его на тикеты, пишет тесты и код, сам себя проверяет и коммитит. Ты утверждаешь план и смотришь итог в pull request.

Скиллы работают в любом харнессе. Проверено в Claude Code, OpenCode и Codex, на моделях Claude и DeepSeek. Чтобы
подключить другой харнесс, скопируй любую секцию в `docs/agents/harness.md` и перепиши под него.

## Кому пригодится

Тому, кто пишет код вместе с агентом, часто один и в нескольких харнессах. Кит нужен, если хочется:

- чтобы агент во всех проектах работал по одному порядку, и его не приходилось каждый раз учить заново;
- чтобы ветки и коммиты были привязаны к задачам в трекере;
- чтобы код проходил тесты и ревью, а в основную ветку агент не пушил никогда.

Для разовой правки или вопроса кит лишний: весь этот порядок там только мешает.

## Что получишь

Один порядок работы во всех проектах. Скиллы общие, а всё, что относится к проекту (команды, трекер, правила кода),
лежит в его `docs/agents/`.

Короткий план. До кода ты читаешь один экран: что получится, по каким признакам это проверить, чего не делаем.
Утверждаешь его один раз, дальше агент приходит к тебе, только если отклонился от плана.

Маленькие шаги. Один тикет даёт один коммит, одна часть задачи даёт один pull request. По карте тикетов видно, что
сделано и что осталось.

Ревью по риску. Агент проверяет каждое изменение и пишет в pull request, от чего защищает каждая проверка. Тебе
остаётся посмотреть места, которые план велит смотреть.

Защищённую основную ветку. Push в неё запрещён в файле прав каждого харнесса. Коммиты агента подписаны его харнессом
(`Claude`, `OpenCode`…), твои подписаны тобой, так что в истории видно, кто что менял.

## С чего начать

Открой [INDEX.md](INDEX.md). Там написано, какие скиллы брать под какой проект, какие работают поодиночке, какие только
набором, как их взять и что поменялось в каждом релизе. Отдай его агенту вместе с описанием проекта, и он подберёт
скиллы сам.

## Установка

1. Склонируй кит:

   ```bash
   git clone git@github.com:DmitryTokyo/agent-kit.git ~/dev/agent/agent-kit
   ```

2. Открой агента в корне проекта и напиши, что делаешь:

   > Прочитай `~/dev/agent/agent-kit/INDEX.md`. Делаю лендинг. Подбери скиллы и возьми их в этот проект, префикс
   > ag.

3. Агент предложит скиллы. Скажешь «да», и он скопирует их в проект, заполнит файлы `docs/agents/`, которые им нужны,
   и спросит то, чего не нашёл в проекте. Для маленького проекта это пара вопросов, для большого долгий разговор.
4. Посмотри `git diff` и закоммить.

После установки скиллы лежат в проекте обычными файлами в `.agents/skills/`. Подгоняй их под проект прямо там: под
стек, трекер, свои привычки и ошибки, которые агент делает именно в этом коде. Что копия разошлась с китом, нормально.
Если правка пригодится в любом проекте, перенеси её в кит и в том же коммите обнови `INDEX.md`. Остальные проекты
получат её при следующем обновлении.

## Как пользоваться

Пиши агенту обычным текстом, нужный скилл подключится сам. В примерах префикс `ag` и ключ задач `AG`.

### Задача целиком

```text
Заведи задачу: покупатель выбирает пункт выдачи на карте.
Напиши план для AG-55.
/ag-to-tickets AG-55
/ag-orchestrate AG-55
```

Сначала `create-plan` оценивает задачу: насколько она важна продукту, что это за работа и чем рискованна. По этой
оценке он выбирает путь. Знакомую задачу можно делать сразу, для новой сначала нужно исследование, а иногда ещё и
дизайн.

Потом он пишет `plan.md`, один короткий файл для тебя: что получится, как это проверить, чего не делаем, нужно ли твоё
ревью. Маленькая задача после плана идёт прямо в `develop`.

Большую `to-tickets` режет на тикеты: тикет до 100 строк кода и один коммит. Тикеты собраны в части, у каждой части
своя ветка и свой pull request. `orchestrate` берёт следующую часть и проводит её тикет за тикетом: субагенты пишут
тесты и код, проверяют их и коммитят.

### Задача, которой сначала нужен дизайн

Так бывает, когда появляется новое поведение, механизм, контракт или взаимодействие:

```text
Исследуй AG-60.        ← /ag-research: сначала разговор о том, что ты хочешь, потом код; research.md
Спроектируй AG-60.     ← /ag-create-design: ты выбираешь подход, агент дотошно расспрашивает; design.md с диаграммами
Напиши план для AG-60.
```

Если работа тянет на несколько задач (новая интеграция, переезд на другой фреймворк), это эпик. Исследование и дизайн
делаются один раз на весь эпик, потом `/ag-to-tasks` пишет roadmap и заводит эпик с задачами в трекере. Документы ты
читаешь в рабочей папке, а каждая утверждённая версия ещё и копируется в трекер.

### Ревью и pull request

```text
/ag-code-review AG-55 pickup-step       ← в новой сессии, лучше другой моделью
/ag-merge-request                       ← пушит и открывает pull request
Я прошёл PR, разбери мои комментарии.   ← ты оставил комментарии на диффе
PR смёржен.                             ← /ag-close-merge-request: трекер, Done, уборка
```

### Без тикетов

```text
Почини: ФИО с точкой в конце не принимается.
Добавь тесты на выбор пункта выдачи.
Подготовь коммит.
Задавай мне вопросы по этому плану по одному.
```

### Обновить скиллы проекта из кита

> Прочитай `~/dev/agent/agent-kit/INDEX.md` и обнови скиллы этого проекта из кита.

## Все скиллы

| Скилл | Что делает |
| --- | --- |
| `create-task` | заводит задачу в трекере |
| `research` | собирает требования и изучает, как система устроена сейчас; пишет `research.md` |
| `brainstorm` | расспрашивает, что ты хочешь и зачем, до любого проектирования |
| `create-design` | согласует с тобой архитектуру: варианты, дотошные вопросы, диаграммы; пишет `design.md` |
| `to-tasks` | режет дизайн эпика на задачи в трекере и пишет их roadmap |
| `create-plan` | оценивает задачу, пишет план для тебя и инструкцию для агента |
| `to-tickets` | режет план на тикеты и части |
| `orchestrate` | проводит следующую часть, один коммит на тикет |
| `tdd-develop` | делает один тикет: сначала тест, потом код |
| `develop` | пишет код без тикета или по тикету без тестов |
| `test-writer` | пишет unit-тесты и E2E-сценарии |
| `integration-test` | пишет один интеграционный тест на задачу: настоящий запрос через весь путь и проверка того, что сохранилось |
| `recon` | изучает незнакомый код перед задачей и возвращает короткую сводку |
| `code-review` | проверяет часть или дифф по правилам и плану, решает, насколько глубоко ревьюить и проверять |
| `hygiene-review` | ищет в изменённых файлах то, что пропускают линтеры |
| `merge-request` | пушит, открывает pull request с тем, что нужно знать человеку, разбирает твои комментарии |
| `close-merge-request` | после слияния: ссылка на pull request в трекер, задача в Done, уборка веток и папки |
| `git-commit-message` | делит изменения на коммиты и предлагает сообщения |
| `grill-one` | задаёт вопросы по плану по одному, ищет дыры и противоречия |
| `business-questions` | ведёт вопросы к бизнесу в трекере; модуль, по умолчанию выключен |

## Как устроено

Раскладка папок, контракт `docs/agents/`, модули, пакеты и метки описаны в [AGENTS.md](AGENTS.md). Их читает агент,
когда правит сам кит.
